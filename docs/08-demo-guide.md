## 1. 如何開啟 Demo

> 以下指令於專案依 [07](./07-frontend-architecture.md) 建立後可用。

| 方式 | 步驟 | 說明 |
| --- | --- | --- |
| 本機開發 | `npm install` → `npm run dev` | 預設 `VITE_DATA_SOURCE=mock`、`VITE_DEMO_MODE=true`；手機實機測試請用 https 預覽或 `localhost` 連線：以區網 IP 的 `http://` 開啟屬非安全環境，瀏覽器不提供 `crypto.subtle`、`crypto.randomUUID` 等 API，送出訂單等流程可能失敗 |
| 本機預覽正式建置 | `npm run build:demo` → `npm run preview` | 驗證實際部署內容 |
| 線上 Demo | 將 `dist/` 部署至任一靜態主機（見 [07 §14.2](./07-frontend-architecture.md)） | 零後端、零設定；開啟網址即可操作 |
| 內用 QR | 於網址加上 `?table=A3` | 桌號 `A1`～`A6`，見 §2.5；不加參數時也可在結帳直接選「內用」，桌號選填、可留空（S10 變體 B） |
| 觸控面板模式 | 於網址加上 `?mode=kiosk`（專用機台以 `VITE_KIOSK_MODE=true` 部署），建議以 1280×800 檢視 | 放大版面、不顯示鍵盤提示與提醒 / 登入 / 記憶；閒置 60 秒警示、90 秒重置（BR-36、BR-37；S18） |
| 鍵盤快速鍵 | 預設**無**字母徽章、單鍵快速鍵關閉；第一次按 `Tab` 後出現鍵盤提醒，按「開啟」才顯示徽章並啟用；啟用後任何頁面按 `?` 查看全部 | 提醒不會位移版面；也可由頂部 ⌨ 按鈕、頁尾「鍵盤快速鍵」，或 Demo 面板「輸入模式」改為「強制啟用快速鍵並顯示徽章」開啟（S16、S17、S26） |
| 設計參考原型 | 開啟 [`assets/mockups/index.html`](./assets/mockups/index.html) | 靜態畫面，僅供確認視覺方向與品牌色；可操作的 Demo 為上列項目（原型說明見 [README](./assets/mockups/README.md)） |

第一次進入會看到 Demo 橫幅：「這是示範站台，資料僅存於你的瀏覽器，不會送出任何訂單」（FR-DM-07）。

## 6. 展示劇本

每個劇本對應 [01 §11 UAT](./01-requirements.md#11-驗收情境uat)（UAT-04 暫停接單為 S3 的變體）。

> **通則**：每個劇本開始前先按 Demo 面板「重置 Demo 資料」（清除訂單、庫存與售完 / 調價覆寫、他人訂單、點餐記憶與鍵盤提醒紀錄，並重新載入），再依該劇本第一步設定時間穿梭；除非劇本另有說明。依序展示多個劇本時同樣適用，否則前一個劇本留下的覆寫會改變後一個的金額與份數（例如 S7 關閉的自動模擬、S8 的紅茶售完、S21 已成立的雙人分享餐）；S7、S8 與 S20 結尾另附還原步驟，供不想整份重置時使用。

### S1 · 手機自取，90 秒點完（UAT-01）

1. 瀏覽器縮到手機寬度（或手機開啟），確認時間為營業中（Demo 面板選「午餐營業」）。
2. 點「招牌滷肉飯」→ 份量選「大碗」→ 加料勾「滷蛋」→ 加入購物車。
3. 回到菜單，點「古早味紅茶」右下 `＋` → 開啟客製化面板（預設已選中杯・半糖・微冰）→ 加入購物車。
4. 點底部「查看購物車」→「前往結帳」→ 取餐方式「自取」、時間「盡快」。
5. 填姓名、手機 → 付款「現金」→ 送出。

**預期**：訂單頁顯示取餐號碼 `A001`（當日第一筆）、狀態「等待店家確認」（自動模擬預設開啟，約 5 秒後轉為「製作中」）、總額 **$92**。

> 若先前載入過點餐記憶範例或登入過示範會員，卡片會多出「上次：…」與「↻ 再點」，且步驟 2 的面板會預選「大碗・滷蛋」並預填備註「不要蔥」——此時**確認已勾選即可，不要重複勾選**（否則會取消）；總額仍為 $92，但購物車品項會帶備註。要回到全新畫面，請以訪客身分於 Demo 面板「點餐記憶」按「清除」。

### S2 · 外送 + 免運 + 折扣碼（UAT-02）

1. 加入 2 份「紅燒牛肉麵」與 1 份「擔仔麵」（小計 `$180×2 + $60 = $420`，≥ $400 免運門檻）。
2. 結帳選「外送」→「新增地址」：臺北市 / 大安區 / `示範路 5 號`（或先「快速登入示範會員」，直接選「家」地址）。
3. 觀察運費顯示「免運」→ 輸入 `LUNCH10`。
4. （選做）改輸入 `FREESHIP`：本單已免運，折抵 $0；再把取餐方式切回「自取」：折扣碼欄位顯示「不適用此取餐方式」（`COUPON_NOT_APPLICABLE`），送出鈕鎖定並說明還有 1 項需要處理；按「移除折扣碼」後總計回到 $420。
5. （選做）改回「外送」，新增地址選新北市 / 板橋區（郵遞區號 `220`）：顯示「超出外送範圍」並提供「改為自取」（`OUT_OF_DELIVERY_AREA`，§2.3）。

**預期**（步驟 3 完成時）：小計 $420、運費 $0（免運）、折扣 −$40（`floor(420×10÷100)=42`，受上限 $40 約束）、總計 **$380**。

### S3 · 午休時段預約取餐（UAT-03）

1. Demo 面板時間穿梭選「午休」（14:30）。
2. 首頁顯示「休息中・17:00 開始營業」；仍可瀏覽與加入購物車。
3. 結帳時「盡快」為停用，預設選取今日 17:00；送出預約單。

**預期**：訂單頁固定顯示「預約 17:00 取餐」；剛送出時為「等待店家確認」，並提示店家將於 16:45 前確認（BR-17：預約單的接單期限不早於「預約時間 − 前置 15 分鐘」）。自動模擬於送出約 5 秒後接單、轉為「製作中」，之後維持到製作基準時間 16:45 才繼續推進，不會因接單逾時被取消（此段期間時間軸的「製作中」僅代表店家已接單，實際開始製作為 16:45；文案以 [03 PG-06](./03-uiux-design.md) 為準）。

> 變體（UAT-04，暫停接單）：Demo 面板「店家狀態」選「暫停接單」→ 進入結帳 → 整頁唯讀、送出鈕停用，並顯示暫停接單說明與店家電話；改回「自動」即恢復。

### S4 · 訂單追蹤與自動推進（FR-OD-02、FR-DM-01）

2. 觀察時間軸依序：等待確認 → 製作中 → 可取餐 → 已取餐；每次變更出現 Toast，頁籤標題前綴「（可取餐）」。
3. 改用速度 5× 或手動按「接單 / 出餐 / 完成」展示控制。

2. 結帳選「LINE Pay」送出 → 進入模擬金流頁，約 1 秒「處理中」後自動顯示付款失敗（已預設結果，見 03 PG-05）。

**預期**：訂單成為 `PENDING`、付款方式現金、付款狀態「取餐時付款」（自動模擬開啟時約 5 秒後轉為「製作中」）。

2. Demo 面板按「快轉 +15 分鐘」，回到訂單頁。

### S7 · 取消訂單（UAT-07）

1. 關閉自動模擬，送出一筆現金訂單 → 於訂單頁按「取消訂單」並確認 → 訂單變「已取消」。
2. 再送出一筆，Demo 面板手動「接單」→ 訂單頁**不再顯示**取消按鈕，改為「致電店家」。

> 步驟 1 要關閉「自動模擬」才能停在「等待店家確認」；自動模擬開啟（預設）時約 5 秒即自動接單，之後不會因接單逾時被取消。要另外展示「接單逾時」：保持自動模擬關閉、不接單，按「快轉 +15 分鐘」（現金單的接單期限預設 10 分鐘），訂單轉為「已取消」（接單逾時）。

> 還原：S7 結束後請把「自動模擬」改回開啟（或「重置 Demo 資料」），以免後續劇本的訂單停在待確認。

### S8 · 售完與價格異動（UAT-08）

1. 購物車放入「招牌滷肉飯」「古早味紅茶」（皆用預設選項：滷肉飯小碗・無加料 $35，紅茶中杯・半糖・微冰 $25）。
2. Demo 面板「商品售完 / 調價」：將「古早味紅茶」設為售完、將「招牌滷肉飯」基本價調為 $40。
3. 進入結帳：頁首狀態列顯示「有 1 項需要調整」，按「查看」展開異動清單。
4. 在清單按紅茶的「移除」，再按送出鈕。

**預期**：只有**一份**異動清單、一次確認：「古早味紅茶」今日售完（動作「移除」）、「招牌滷肉飯」價格已更新 $35 → $40（價格更新不計入需處理的項目數）；處理完前送出鈕鎖定並說明還有幾項需要處理。移除紅茶後，送出鈕變為「確認新價格並送出 · $40」，金額與清單一致；價格差異已在步驟 3 展開，按一次即成立訂單，總額 $40。

> 總額增加時，若價格差異尚未展開，第一次按送出鈕（或 `Ctrl/⌘ + Enter`）只會展開並聚焦差異，確認後再按一次才送出；僅降價或價格不變可一鍵送出。
>
> 狀態列的項數只計需要處理的異動：若只有價格更新（例如只把滷肉飯基本價調為 $40、紅茶維持上架），狀態列改為「有 1 項價格更新〔查看〕」，不顯示「有 0 項需要調整」。
>
> 還原：Demo 面板「商品售完 / 調價」將古早味紅茶恢復上架、招牌滷肉飯基本價改回 $35（或直接「重置 Demo 資料」），以免影響後續劇本的金額與可點品項。

### S10 · 內用點餐：QR 帶桌號與沒有桌號（UAT-10）

**變體 A：掃 QR，有桌號**

1. 先「重置 Demo 資料」，以 `/?table=A3` 進入（模擬掃描桌上 QR Code；種子桌位為 `A1`～`A6`，見 §2.5）。
2. 菜單頂部顯示「內用・桌號 A3」；加入「招牌滷肉飯」「古早味紅茶」→ 進入結帳。
3. 取餐方式已鎖定為「內用」，桌號帶入且不可改成不存在的桌號；付款選「現金」→ 送出。

**預期**：無運費；取餐號碼前綴 `T`（例：`T001`）；訂單頁取餐資訊列顯示「內用・巷仔內小吃部・桌號 A3」。

**變體 B：不掃 QR，沒有桌號（自由入座、先領餐號叫號）**

1. 「重置 Demo 資料」後以 `/` 進入（不帶 `?table=`），加入餐點 → 進入結帳。
2. ① 取餐方式選「內用」：③ 內用區顯示「桌號（選填）」與提示「沒有桌號可以留空，餐點好了會依取餐號碼叫號」；姓名、手機也可留空。
3. **不輸入桌號**，付款選「現金」→ 送出。

**預期**：送出成功（請求不帶桌號，不會出現 `TABLE_NOT_FOUND`）；無運費；訂單頁狀態卡顯示取餐號碼 `T001`，頁面標題為「訂單追蹤・T001」，取餐資訊列為「內用・巷仔內小吃部・取餐號碼 T001」，**沒有**「桌號」列（不是空白列，也不顯示「桌號 undefined」）；「查詢訂單」的本機記錄與 Demo 面板本來就只列取餐號碼與取餐方式，不顯示桌號。

**變體 C：手動輸入桌號**

1. 同變體 B 的步驟 1～2，在桌號欄輸入 `Z99`（格式合法但不是店家桌位）→ 送出。
2. 被退回並留在結帳頁：異動清單的「折扣 / 付款 / 發票 / 外送條件」類列出桌號，定位到桌號欄並顯示「找不到這個桌號，請洽店員協助」，其餘欄位保留。
3. 改為 `A3`（或清空桌號）→ 再送出。

**預期**：步驟 1 不建立訂單（有輸入的未知桌號不會被當成「沒有桌號」放行）；改為 `A3` 後訂單頁顯示「桌號 A3」；清空則同變體 B。

**變體 D：QR 無法辨識與觸控面板**

- 以 `/?table=Z99` 進入：菜單頂部提示「找不到 QR 帶入的桌號，已改為一般點餐；要內用請改選「內用」（桌號可留空），或洽店員」，取餐方式不鎖定；改選「內用」後仍可留空桌號下單。
- `?mode=kiosk`（S18）：取餐方式只有「外帶」「內用」，沒有桌號欄，內用單一律無桌號（不套用 `?table=`），送出後只顯示取餐號碼。

### S13 · 精簡菜單點餐（UAT-13）

1. Demo 面板「菜單資料」選「精簡」，以手機寬度檢視。
2. 觀察菜單：清單版面，每列只有品名與價格；沒有圖片區、空白描述行或標籤。
3. 點兩項商品的「＋」→ 直接加入（不彈出面板），卡片動作區變為 `− 1 ＋`。
4. 開啟購物車：品項為單行「品名 + 價格」→ 結帳 → 送出。

**預期**：全程無破圖與空白區塊，可完成下單。再切到「無圖片」與「部分缺圖」，比較圖卡的佔位圖塊與清單的縮圖對齊。

### S14 · 主題色與對比（UAT-14）

1. 以桌機寬度開啟菜單。
2. Demo 面板「主題色」依序切換 7 組。
3. 每組觀察：主要按鈕、選取中的分類膠囊、連結與焦點外框（以 Tab 鍵移動）。

**預期**：每組皆立即套用新主題且文字清晰（對比 ≥ 4.5:1）；切到「檸檬黃」時主要按鈕文字變為深色；錯誤訊息（如手機格式錯誤）始終維持 danger 紅，不隨主題改變。

### S15 · 全程免登入（UAT-15）

1. 保持未登入：加入商品 → 結帳 → 勾選「記住我的資料」→ 送出。
2. 訂單頁出現淡色提示「想保存這筆訂單？」→ 按 ✕ 關閉。
3. 關閉分頁後重新開啟；底部「訂單」→「查詢訂單」，輸入訂單編號與手機（或點選本機記錄）。
4. 再點一份餐進入結帳：姓名與手機已預填。

**預期**：全程未出現強制登入；可查到該訂單與進度；提示關閉後不再出現。

### S16 · 純鍵盤點餐（UAT-16；選做 UAT-18）

1. 桌機寬度、未登入、**不碰滑鼠**；先以 Demo 面板選「午餐營業」並收合面板（面板展開時提醒會待命），「輸入模式」維持「自動」。
2. 在菜單頁第一次按 `Tab`：焦點移到「跳到主要內容」，同時頂部 ⌨ 按鈕下方浮出「偵測到實體鍵盤」提醒——頁面排版與焦點都不變；此時**沒有**任何字母徽章（單鍵快速鍵預設關閉）。
3. 連按 `Tab` 越過其餘跳過連結，焦點到提醒的「開啟」→ `Enter`：各控制項旁才出現小寫字母徽章（搜尋 `s`、購物車 `c`、版面 `v` …）；徽章是使用者主動開啟的結果，允許局部重排，但「編輯」「移除」等功能控制項不會被隱藏或移動。也可改由頂部 ⌨ 按鈕、頁尾「鍵盤快速鍵」或最後一個跳過連結「鍵盤快速鍵與偏好」開啟對話框，打開「啟用單鍵快速鍵」（開啟過對話框後，本次載入不再跳出提醒）。
4. 按 `s` 進入搜尋，輸入「滷」→ 按 `↓`（或 `Enter`）把焦點移到第一個結果「招牌滷肉飯」→ `Enter` 開啟商品面板（焦點移入面板標題）。
5. 按 `Tab` 進入「份量」群組，以 `↓` 選「大碗」→ 再按 `Tab` 進入「加料」，`Space` 勾「滷蛋」→ 按 `a` 加入購物車（焦點回到商品卡；選項群組上的焦點不影響 `a`）。
6. 按 `c`：桌機寬度會把焦點移到右側「我的訂單」面板（窄螢幕則開啟購物車抽屜）→ 按 `p` 前往結帳。
7. `Tab` 填姓名、手機（輸入框內打 `c`、`p` 不會觸發快速鍵）→ 付款方式以方向鍵選「現金」。
8. 按 `Ctrl + Enter`（macOS 為 `⌘ + Enter`）送出訂單。
9. （選做・UAT-18）開啟 VoiceOver（macOS：`⌘ + F5`）或 NVDA，重做 S1：確認品名與價格、必選選項錯誤、加入購物車結果與訂單狀態變更皆被朗讀。

**預期**：全程不需要滑鼠；每個停點都有可見的焦點外框；提醒出現前後版面位置不變（按「開啟」後徽章出現時允許局部重排，但不得隱藏或移動「編輯」「移除」等功能控制項）；送出後焦點移到訂單頁標題。

> 單鍵快速鍵不是必要條件：不開啟時，僅以 `Tab`、方向鍵、`Enter` 與 `Ctrl/⌘ + Enter` 重做一次同樣可以完成（見 S25）。

### S17 · 快速鍵說明與關閉（UAT-17）

1. 桌機寬度、全新狀態（面板「重置 Demo 資料」並收合面板、「輸入模式」維持「自動」），在菜單頁確認沒有任何字母徽章。按 `?` 或 `c`：**沒有**說明對話框、購物車也不會開啟（單鍵快速鍵預設關閉，`?` 也不例外）；這次按鍵會觸發鍵盤提醒，說明剛才按的鍵是快速鍵、目前尚未開啟。
2. 在提醒按「開啟」（或經頂部 ⌨ 按鈕、頁尾「鍵盤快速鍵」打開對話框後開啟「啟用單鍵快速鍵」）：字母徽章出現。
3. 按 `?`：開啟「鍵盤快速鍵」對話框，列出全部快速鍵；按 `Esc` 關閉，焦點回到原處。
4. 按 `s` 進入搜尋框，輸入 `c`、`o`：只會輸入文字，不會開啟購物車或訂單頁。
5. 按 `Esc`（清除文字並離開搜尋框）後按 `c`：桌機焦點移到「我的訂單」面板，窄螢幕開啟購物車抽屜。（選做）切到注音輸入法再按一次；非輸入元件焦點下通常仍可觸發，實際行為依瀏覽器與輸入法而異。
6. 再按 `?`，把「啟用單鍵快速鍵」關閉（偏好設定在同一個對話框內）→ 關掉對話框 → 按 `c`：**沒有反應**，`?` 也不再生效（要看說明請由頂部 ⌨ 按鈕或頁尾「鍵盤快速鍵」進入）；開啟任一商品面板後按 `Esc` 仍可關閉、在結帳頁按 `Ctrl/⌘ + Enter` 送單仍然有效。重新整理後仍維持關閉，且**不會**再跳出鍵盤提醒（已處理過）。
7. 展示現場要再看一次提醒：Demo 面板按「重播鍵盤提醒」並收合面板（見 S26）。

**預期**：說明內容與畫面上的徽章一致；未啟用、輸入框內與停用後都不觸發單鍵快速鍵；`Esc` 與 `Ctrl/⌘ + Enter` 不受開關影響；提醒的出現不改變版面。

### S18 · 觸控面板與閒置重置（UAT-19）

1. 先按「重置 Demo 資料」（確保沒有一般模式留下的資料），再於網址加上 `?mode=kiosk`（僅 Demo 模式有效；或 Demo 面板「輸入模式」選「觸控面板」），視窗 1280×800。
2. 觀察：按鈕與卡片明顯放大、右側常駐訂單面板、**沒有**鍵盤字母徽章，也不會出現鍵盤偵測提醒（按 `Tab`、`c`、`?` 都不會跳出提醒，`c`、`?` 也沒有快速鍵效果；`Esc` 與 `Ctrl/⌘ + Enter` 仍有效）、登入與查詢訂單入口隱藏、結帳沒有「記住我的資料」、付款方式只有「現金（櫃檯付款）」，取餐方式只有「外帶」「內用」且內用沒有桌號欄（內用單一律無桌號，不因缺桌號被擋下，S10 變體 D）。
3. 加入兩項餐點後**不再操作**：約 60 秒出現「還在嗎？」警示與倒數；按「繼續點餐」→ 倒數消失並重新計時。
4. 再次放著不動，約 90 秒時購物車被清空並回到菜單首頁。
5. 完成一筆現金訂單：完成畫面以超大字顯示取餐號碼；30 秒後自動回到首頁，也可按「開始新訂單」立即回去，或按「再看一下」重新計 30 秒。
6. 收尾：以 `?mode=default` 或 Demo 面板「輸入模式」改回「自動」，回到一般模式。

**預期**：所有可點目標 ≥ 56×56 px、不需要 hover；警示可延長；重置後不殘留前一位的購物車與個資（觸控面板期間用戶端儲存只在記憶體：開發者工具 → Application → Local Storage 的 `zaiorder:v1:cart`、`session`、`prefs`、`guestOrders` 不會新增或變更）。閒置計時使用實際時間，不受「時間穿梭」影響。結果未知（送出時回應遺失）後的重置會一併丟棄 Idempotency-Key 與記下的送出內容，驗證見 S24 變體 C（`?mode=kiosk&demo_fail=orders.create:AFTER_COMMIT:1`）。

### S19 · 上次選項快速點餐（UAT-20）

1. 以訪客身分，Demo 面板「點餐記憶」→「載入範例」。
2. 回到菜單：菜單頂部出現「常點的餐點」；「招牌滷肉飯」卡片顯示「上次：大碗・滷蛋」與「↻ 再點」。
3. 點「↻ 再點」：購物車新增 1 份「大碗・滷蛋」，**不彈出面板**；Toast「已再點：招牌滷肉飯（大碗・滷蛋）」，可按「復原」。
4. 點同一張卡的「＋」：面板預設已選大碗與滷蛋、備註預填「不要蔥」，品名下方顯示「已套用上次的選擇：大碗・滷蛋　恢復預設」；按「恢復預設」→ 小碗、無加料。
5. 點「鹽酥雞」的「↻ 再點」：因上次的「特辣」已不提供，改為開啟面板並提示「部分選項已不提供，已改用預設」；梅子粉保留、辣度改回預設「不辣」。
6. （選做）由頂部 ⌨ 按鈕（窄螢幕用頁尾「偏好設定」）開啟「鍵盤快速鍵與偏好」，關閉「記住上次點過的選項」→ 回到菜單，「上次」「↻ 再點」與「常點」皆消失；或登入示範會員（S9）觀察常點來自歷史訂單。

**預期**：一鍵再點不需任何選擇即可加入；記憶不會在使用者不知情下套用已失效的選項；關閉記憶後完全不顯示。

### S20 · 送出當下才售完（UAT-21）

1. Demo 面板時間穿梭選「午餐營業」；購物車放入「古早味紅茶」與「招牌滷肉飯」，進入結帳：取餐方式「自取」、時間「盡快」，填姓名、手機，付款「現金」（先不要送出）。
2. 打開 Demo 面板「庫存與時段情境」：「商品」選「古早味紅茶」→「下一次送出前才發生」選「商品變售完」→ 按「預備」（面板顯示「已預備」，浮動按鈕出現小圓點）。
3. 回到結帳頁按「送出訂單」。

**預期**：訂單**沒有**建立、仍停在結帳頁；異動清單就地展開並聚焦標題，列出「古早味紅茶　剛剛被訂走了」（動作「移除」）；已填的姓名、手機與取餐時間都還在。面板「最近送出紀錄」新增一筆被拒紀錄（原因為商品今日售完，格式見 [03 PG-18](./03-uiux-design.md)），「查詢訂單」的本機記錄沒有新單。按「移除」後再按「送出訂單」即成立（整個恢復過程不超過 2 次點擊）。

> 進入結帳時一切正常、按下送出才被拒：預備的情境只在送出訂單的交易內才發生，試算（quote）不受影響——展示的正是「購物車與試算只是預檢，送出時才做最後確認」。
>
> 還原：預備的「商品變售完」在送出時已把古早味紅茶設為手動售完；請於面板「商品售完 / 調價」將它恢復上架（或「重置 Demo 資料」），以免影響後續劇本。

4. 清單顯示「雙人分享餐　今日只剩 2 份（已選 3 份）」，送出鈕鎖定並說明還有 1 項需要處理。按「全部套用建議」：出現摘要「已調整：雙人分享餐改為 2 份」，金額更新為 $598。（選做）按「復原」回到 3 份（仍標示不足），再套用一次。

### S22 · 預約時段送出時額滿，改選最近時段（UAT-23）

1. Demo 面板時間穿梭選「午餐營業」（12:00）；購物車放入任一商品，進入結帳：取餐方式「自取」、時間改選預約今日 12:30，填姓名、手機，付款「現金」（先不要送出）。時間穿梭會繼續走時，請在選定時間後 15 分鐘內完成步驟 3，否則 12:30 時段會因不足前置時間而消失。
2. Demo 面板「庫存與時段情境」：「預約時段」選今天 12:30 →「下一次送出前才發生」選「時段額滿」→ 按「預備」。
3. 回到結帳頁按「送出訂單」。
4. 清單提示「12:30 這個時段已額滿」，並提供「改選 12:45」與「選其他時段」；原本的時段選取已清除，不會自動選取。按「改選 12:45」→ 再按「送出訂單」。

**預期**：訂單成立，訂單頁顯示「預約 12:45 取餐」（不是 12:30）；已填的姓名、手機與付款方式不需重填。

> 變體：改在「預約時段」按「只剩 1 個名額」（讀數「已訂 7 / 8」）後送出 → 仍可成立並佔用最後一個名額（讀數「已訂 8 / 8」），此後同一時段再送出才會被拒。若直接按「讓此時段額滿」立即補滿，結帳頁會在背景偵測後只更新狀態列與送出鈕（不展開清單、不位移版面、不搶走焦點），按「查看」才展開清單。選「盡快」的即時單目前不計入單時段上限（01 Q-11），不受時段額滿影響。

### S23 · 付款期間保留與逾時釋放（UAT-24）

1. 先按 Demo 面板「重置 Demo 資料」（先前劇本成立的訂單與他人訂單都會清除，雙人分享餐回到剩 5 份），再於時間穿梭選「午餐營業」；「付款結果」維持「手動」。
2. 加入 3 份「雙人分享餐」（主餐勾兩項）→ 結帳 → 付款選「LINE Pay」→ 送出，停在付款頁：顯示「已保留餐點與取餐時段，請於 HH:mm 前完成付款」與 15:00 倒數。
3. 看 Demo 面板讀數（或回到菜單、另開分頁看卡片）：「今日已售 0・待付款保留 3・剩 2 份」，菜單卡顯示「剩 2 份」。
4. 按「快轉 +15 分鐘」，回到訂單頁。

**預期**：訂單為「已取消」，原因「付款逾時」，並說明保留的餐點與時段已釋出、可按「再來一單」；菜單回到「剩 5 份」，面板讀數的待付款保留歸零。

> 變體（立即釋放）：改以「現金」送出 ×3（剩 2 份），先關閉自動模擬，再於面板手動「拒單」→ 立刻回到「剩 5 份」。取消、拒單與逾時都會釋放；現金單沒有 15 分鐘付款期限，會保留到店家接單、拒單、顧客取消或接單逾時為止（接單期限自送出起算，預設 10 分鐘；預約單最長到預約時間前）。接單逾時只在自動模擬關閉、店家未接單時發生：保持自動模擬關閉再快轉 +15 分鐘，即可觀察即時單逾時；自動模擬開啟時約 5 秒即接單，快轉後仍為已接單，不會逾時。

### S24 · 連點與回應遺失只建立一筆（UAT-25）

1. 購物車放入任一商品，進入結帳並填妥（付款「現金」）。
2. Demo 面板「送出結果」→「下一次送出訂單」選「回應遺失，訂單已建立」。
3. 按「送出訂單」：約 1 秒後仍停在結帳頁，顯示「無法確認訂單是否已送出」的提示，說明再試一次不會重複下單，並提供「再試一次」與店家電話（致電確認）；已填的資料與付款方式都還在。
4. 按「再試一次」。

**預期**：進入訂單頁並提示「訂單已成立」；底部「訂單」→「查詢訂單」的本機記錄比送出前只多 **1 筆**；面板「最近送出紀錄」依序出現「回應遺失（訂單已建立）」與「重送 → 取回原訂單（未重複建立）」；限量商品只扣一次、取餐號碼不跳號。

> 變體 A（內容改變）：第 3 步之後回到購物車，編輯品項備註（或改數量）再回結帳按送出 → 導向先前成立的訂單，提示「稍早送出的訂單已成立，內容與目前購物車不同」；購物車保留，如需調整請先取消該訂單再重新下單。只改結帳頁的訂單備註、時段或付款方式不算內容不同（訂單層級欄位不參與比對），仍視為同一筆並清除購物車。
>
> 變體 B（連點）：快速連點「送出訂單」，或與 `Ctrl/⌘ + Enter` 並用 → 只建立 1 筆（送出中按鈕為 `aria-disabled` + `aria-busy`、焦點保留，再次點擊與 `Ctrl/⌘ + Enter` 依 `decideSubmit` 視為送出中而不動作；後端以同一把 Idempotency-Key 序列化）。
>
> 變體 C（選做，觸控面板）：觸控面板模式不顯示「送出結果」區塊，請以啟動參數佈置：`?mode=kiosk&demo_fail=orders.create:AFTER_COMMIT:1`，送出現金單 → 改顯示「請洽櫃檯確認」與「再試一次」（沒有店家電話連結與「查詢訂單」）。放著不動時，約 60 秒的閒置警示照常出現並多一行「上一筆訂單結果尚未確認，請洽櫃檯確認」；90 秒重置時一併丟棄 Idempotency-Key 與記下的送出內容，下一位顧客使用新的 Key（重複下單的風險交由櫃檯確認承擔）。

### S25 · 異動清單純鍵盤處理（UAT-26；選做螢幕閱讀器）

1. 購物車放入「雙人分享餐」×3 與「古早味紅茶」；Demo 面板將紅茶設為售完、雙人分享餐設為「剩 2 份」。之後**不碰滑鼠**，「輸入模式」維持「自動」（不需開啟單鍵快速鍵）。
2. 以 `Tab` / `Enter` 前往結帳，`Tab` 填妥姓名、手機，付款方式以方向鍵選「現金」。
3. 在送出鈕鎖定時按 `Ctrl/⌘ + Enter`：不會送出；清單展開，焦點與捲動移到清單標題，並通報「還有 2 項需要處理」。
4. `Tab` 依序到各項動作鈕（名稱含品名，例如「移除古早味紅茶」「將雙人分享餐改為 2 份」），`Enter` 執行。每處理一項，焦點移到下一個異動項的主要動作；最後一項處理完，焦點移到送出鈕。
5. 按 `Enter`（或 `Ctrl/⌘ + Enter`）送出。
6. （選做）開啟 VoiceOver 或 NVDA 重做：送出被退回時摘要只朗讀一次；單項調整後以 polite 合併為一句通報（格式見 [03 §10.4](./03-uiux-design.md)，例如先處理雙人分享餐時為「已改為 2 份，金額 $598，還有 1 項需要處理」）；改按「全部套用建議」則通報「已調整 2 項，可以送出了」。

**預期**：全程不需滑鼠；每個動作鈕的名稱含品名；鎖定時 `Ctrl/⌘ + Enter` 只聚焦清單、不送出；成功後焦點移到訂單頁標題。

### S26 · 鍵盤偵測提醒不位移版面（UAT-27）

1. 桌機寬度（1440×900）、全新狀態：Demo 面板按「重置 Demo 資料」，「輸入模式」維持「自動」，並收合面板。開啟菜單頁，記下分類膠囊、商品卡與右側「我的訂單」面板的位置。
2. 觀察：**沒有**任何小寫字母徽章；頂部右側有 ⌨ 按鈕（「鍵盤快速鍵與偏好」）。
3. 按 `Tab` 一次：焦點到「跳到主要內容」，並在 ⌨ 按鈕下方浮出「偵測到實體鍵盤」提醒卡（「開啟」「不用了」）。比對：所有元件的位置**完全沒有移動**，提醒也沒有蓋住「我的訂單」面板的「前往結帳」。
4. 連按 `Tab` 到「開啟」→ `Enter`：卡片轉為「已開啟單鍵快速鍵」的確認，數秒後收起；各控制項旁才出現小寫字母徽章（使用者主動開啟，允許局部重排，但「編輯」「移除」等功能控制項不會被隱藏或移動）；按 `c` 把焦點移到「我的訂單」面板。
5. 重新整理：不再出現提醒，徽章仍在（偏好已記住）。

**預期**：預設無徽章；提醒出現前後版面位置不變、不搶走焦點、不遮住主要操作；按「開啟」後徽章才出現（允許局部重排）、單鍵快速鍵才生效；之後不再提醒。

> 變體「不用了」：Demo 面板按「重播鍵盤提醒」（提醒先待命，不受時間限制）並收合面板 → 提醒出現 → 按「不用了」→ 之後不再自動提醒；入口仍在（⌨ 按鈕、頁尾「鍵盤快速鍵」、跳過連結「鍵盤快速鍵與偏好」；結帳與付款頁同樣保留）。
>
> 變體「逾時」（桌機 / 平板，≥ 768）：不處理，約 12 秒後提醒收起並轉為 ⌨ 按鈕上的小圓點（不佔版面、不消失；滑鼠移入或焦點進入會暫停計時），點 ⌨ 仍可開啟偏好並清除圓點（換頁不會清除）。
>
> 變體「第一個按鍵就是快速鍵」：重置後直接按 `c` → 購物車不會開啟，提醒改為說明「剛才按的「c」是快速鍵，目前尚未開啟」。
>
> 變體「手機」（< 768；桌機瀏覽器縮窄視窗即可）：提醒位於購物車列與底部分頁之上（與 Toast 同一位置），與 Demo 浮動按鈕不相交；沒有 ⌨ 按鈕，不處理約 12 秒後直接收起（沒有小圓點），入口為頁尾「鍵盤快速鍵」與跳過連結「鍵盤快速鍵與偏好」；結帳與付款頁不會出現提醒。
>
> 變體「觸控面板」：`?mode=kiosk` 下按 `Tab`、`c`、`?` 都不偵測、不提醒（S18）。

## 7. 10 分鐘對外展示建議流程

| 分鐘 | 內容 | 劇本 |
| --- | --- | --- |
| 0–2 | 手機寬度瀏覽菜單、搜尋、客製化 | S1 前半 |
| 2–4 | 結帳（自取、預約、發票、折扣碼），送出訂單 | S1、S3；發票見 S12、折扣碼見 S2 |

| 6–7 | 外送：運費與門檻、超出範圍 | S2（含選做的超出範圍步驟） |
| 7–8 | 付款失敗與取消 | S5、S7 |
| 8–9 | 休息中 / 暫停接單狀態 | S3（含暫停接單變體）+ Demo 面板 |
| 9–10 | 拉寬至桌機版型；說明「後續串接 API 不需改 UI」 | S11 |

> 依序展示時，請依 §6 通則於各劇本前先「重置 Demo 資料」，或確認前一劇本未留下覆寫（時間穿梭、自動模擬關閉、付款結果）時才省略（上表中，S3 會留下時間穿梭、S7 會關閉自動模擬，S5 預設的付款結果用過一次即回到「手動」）；加入 S8、S20～S25 這類會留下覆寫或訂單的劇本時，務必先還原或重置。
>
> 若時間允許，可加 2 分鐘展示「**業態通用**」：S13（精簡菜單）與 S14（切換主題色），說明同一套介面如何套用到飲料店、咖啡廳等不同餐飲業。

> 想強調「回訪者與多輸入裝置」可再加 2–3 分鐘：S19（一鍵再點上次的選項）、S16 / S17 / S26（純鍵盤、快速鍵說明與鍵盤提醒）、S18（觸控面板與閒置重置）。

## 8. 已知限制

| 項目 | 說明 |
| --- | --- |
| 資料範圍 | 僅存於目前瀏覽器；清除網站資料、換裝置後不保留；無痕視窗關閉後即清除；若環境停用網站資料（或舊版瀏覽器 / WebView 限制）則降級為記憶體，重新整理後不保留 |
| 訪客訂單與登入 | 登入前以訪客身分下的訂單**不會**併入會員歷史（歸戶屬 FR-AC-08，P2）；可由「訂單 → 查詢訂單」的本機記錄查看 |
| 多分頁 | 多個分頁共用同一份 `localStorage`。送出訂單與所有會寫入資料的動作（惰性推進、取消、付款、店家模擬動作、會員資料與 Demo 面板操作）都經 Web Locks 取得鎖後先重讀、再變更並同步寫回（偏好、購物車等 UI 儲存另以防抖寫入，不在此列），兩個分頁同時搶最後 1 份只會成功 1 筆；讀取以輪詢最終一致。**不支援 Web Locks 的瀏覽器 / WebView** 降級為單分頁保證，多分頁同時操作可能遺失寫入或超賣（正式環境由後端交易保證） |
| 庫存與並行 | Mock 為單執行緒，以同步臨界區與「預備下一次送出前的情境」確定性重現搶購，無法暴露真實並行；超賣的保證由後端的並行契約測試驗證（01 R-06、R-08） |
| 暫時額滿的顯示 | 他人尚未付款的訂單仍占用份數，菜單顯示「今日售完」；送出被退回時會補充說明他人的訂單逾時未付款或被取消時份數可能釋出，稍後再試可能又可購買（01 Q-15 預設不新增「暫時額滿」狀態） |
| 手動售完與限量覆寫 | 不模擬「營業日結束後自動重置」（01 Q-12）：以面板設定的手動售完與每日限量覆寫會一直保留，需手動恢復或「重置 Demo 資料」；快轉 +24 小時不會重置它們 |
| 時間穿梭往回撥 | 不保證可逆：已取消的訂單不會復活，尚未結算的逾期待付款訂單可能重新計入份數；要回到乾淨狀態請「重置 Demo 資料」 |
| 他人訂單 | 「模擬他人下單」與「預備」注入的訂單以 `X` 開頭的取餐號碼辨識（例如 `X001`），只用來占用份數與時段：不出現在「歷史訂單」「查詢訂單」，手動店家操作不作用於它們，也不影響 `A` / `D` / `T` 的取餐號碼序號；正式環境沒有此概念 |
| 結果未知與重送 | 重送用的 Idempotency-Key 存於 `sessionStorage`，重新整理後仍可「再試一次」；關閉分頁後重新開始會產生新的 Key，可能重複建立訂單（屬可接受限制，請致電店家確認）；觸控面板模式僅存記憶體，閒置重置時一併丟棄 Key 與記下的送出內容（下一位顧客使用新 Key，結果未知的訂單請洽櫃檯確認） |
| 金流 / 發票 / 簡訊 | 全為模擬，不會產生實際扣款、發票或簡訊 |
| 店家端 | 無店家後台；訂單推進由 Demo 模擬器負責 |
| 圖片 | 為佔位圖，非實際商品照片 |
| 點餐記憶 | 訪客記憶僅存於目前瀏覽器（180 天、最多 100 項）；示範會員的常點由歷史訂單推導，只有「重置 Demo 資料」會還原；觸控面板模式不記錄也不套用 |
| 鍵盤與螢幕閱讀器 | 單鍵快速鍵**預設未啟用**，可由鍵盤提醒的「開啟」、頂部 ⌨ 按鈕或頁尾「鍵盤快速鍵」開啟與停用；快速鍵依實體鍵位比對，部分瀏覽器擴充功能或螢幕閱讀器的單鍵導覽模式可能攔截按鍵（使用螢幕閱讀器者建議保持關閉）。實體鍵盤只以第一次可信的實體按鍵偵測：外接鍵盤的手機 / 平板（沒有滑鼠或觸控板）需按到 `Tab`，或 10 秒內連按 3 次以上（含至少一次非 `Enter` 的按鍵）才會提醒；軟鍵盤與輸入法組字不會誤報。焦點已在頁面中段時按到快速鍵（例如在第 8 張商品卡按 `c`），提醒需 `Shift + Tab` 回到頁首才到得了，12 秒內可能來不及；錯過不影響功能，入口仍在。選「不用了」後只能以「重播鍵盤提醒」或重置還原 |
| 觸控面板 | 為瀏覽器內的模擬模式：不控制全螢幕、不鎖定系統介面，也不連接真實機台、印表機或線上金流（僅櫃檯付款）；閒置計時使用實際時間；用戶端儲存僅存記憶體，重新整理即清空 |
| 搜尋引擎 | 站台含 `noindex`，不會被收錄 |
| 時間 | 時間穿梭只影響前端 Mock，不影響裝置時鐘；鍵盤提醒的出現間隔（24 小時）與觸控面板的閒置計時使用實際時間，不受時間穿梭影響 |

## 9. 疑難排解

| 現象 | 原因 / 處理 |
| --- | --- |
| 看不到 Demo 面板 | `VITE_DEMO_MODE` 非 `true`；請重新建置或設定環境變數 |
| 營業狀態與預期不同 | 檢查是否殘留時間穿梭設定；於面板選「實際時間」或重置 |
| 購物車突然變空 | 超過 24 小時自動清除，或曾重置 Demo 資料 |
| 登入收不到驗證碼 | Demo 無簡訊；驗證碼固定 `123456` |
| 重新整理後資料消失 | 瀏覽器停用了網站資料或環境不支援 `localStorage`（已降級為記憶體），畫面會有一次性提示；無痕視窗關閉後資料也會清除 |
| 按 `c`、`s` 等快速鍵沒反應 | 尚未啟用單鍵快速鍵（預設關閉，`?` 也一樣）、焦點在輸入框、輸入法正在組字、已於偏好設定停用、處於觸控面板模式，或有按住 Ctrl / ⌘ / Alt；請先於鍵盤提醒按「開啟」 |
| 看不到字母徽章 | 預設隱藏：需在鍵盤提醒按「開啟」，或由頂部 ⌨ 按鈕 / 頁尾「鍵盤快速鍵」開啟「啟用單鍵快速鍵」；或在 Demo 面板「輸入模式」選「強制啟用快速鍵並顯示徽章」（觸控面板模式永不顯示） |
| 沒有出現鍵盤提醒 | 已按過「開啟」或「不用了」、已開啟過「鍵盤快速鍵與偏好」對話框、本次載入已提醒過（含顯示中被 Toast / 浮層 / Demo 面板搶走而收起）、此裝置已提醒 2 次（第二次需間隔 24 小時）、目前有 Toast / 浮層 / 展開的 Demo 面板（尚未顯示者待命，關閉後才顯示）、位於結帳或付款頁、視窗高度不足 480 px、輸入框內打字，或處於觸控面板模式；展示時請用 Demo 面板「重播鍵盤提醒」並收合面板 |
| 提醒不見了，只剩 ⌨ 上的小圓點 | 提醒約 12 秒未處理即收起並轉為頂部 ⌨ 按鈕上的小圓點（≥ 768），屬預期；點 ⌨ 或開啟「鍵盤快速鍵與偏好」才清除，換頁不會清除；< 768 沒有 ⌨ 按鈕，逾時直接收起（入口為頁尾「鍵盤快速鍵」與跳過連結「鍵盤快速鍵與偏好」）。注意：Demo 浮動按鈕上的小圓點是「已預備下一次送出的模擬」，兩者不同 |
| 顯示剩 5 份但送出被拒 | 他人搶購（面板「模擬他人下單」或已預備「下一次送出前」的情境），或自己另有待付款訂單保留中；送出時才做最終確認，與菜單顯示可能不同。到面板「庫存與時段情境」看讀數（已售 / 待付款保留 / 剩餘），或按「取消預備」「清除他人訂單」 |
| 快轉後庫存沒回來 | 確認該單為「待付款」的線上付款訂單且已超過 15 分鐘付款期限；現金單沒有付款期限，會保留到店家接單、拒單、顧客取消或接單逾時（自送出起算，預設 10 分鐘；預約單最長到預約時間前），且接單逾時只在自動模擬關閉時發生（開啟時約 5 秒即接單，快轉後仍為已接單）；已取餐的訂單屬已售，不會釋放；快轉 +24 小時換營業日後，昨日訂單不計入今日 |
| Demo 浮動按鈕有小圓點 | 面板中有已預備、尚未發生的「下一次送出前」情境，或「下一次送出訂單」不是「正常」；按「取消預備」或改回「正常」即可清除 |
| 送出後顯示「無法確認訂單是否已送出」 | 面板「送出結果」設為「回應遺失」或「失敗，未建立訂單」，或以 `demo_fail` / 網路注入了失敗（皆展示為結果未知）；按「再試一次」即可，不會重複建立訂單（S24） |
| 看到 `X001` 開頭的取餐號碼 | 那是面板「模擬他人下單」注入的訂單，只占用份數與時段，不屬於你的訂單；可按「清除他人訂單」移除 |
| 沒有「上次」或「常點」 | 此裝置尚未完成過訂單、已關閉點餐記憶，或處於觸控面板模式；於 Demo 面板「點餐記憶」按「載入範例」 |
| 按「↻ 再點」卻開啟面板 | 上次的選項已部分失效或商品已調整；面板會標示「部分選項已不提供」，確認後再加入 |
| 觸控面板模式突然回到首頁 | 閒置超過 90 秒的自動重置，屬預期行為；警示出現時按「繼續點餐」可延長 |
| 訂單頁沒有「桌號」列，或結帳看不到桌號欄 | 屬預期：內用桌號為選填，沒有輸入桌號（或 `?table=` 無法辨識）時訂單頁不顯示桌號列，取餐資訊列改為「內用・巷仔內小吃部・取餐號碼 T001」；觸控面板模式沒有桌號欄，內用單一律無桌號。要有桌號請以 `/?table=A3` 進入或在結帳輸入 `A1`～`A6`（S10） |
| 想回到全新狀態 | Demo 面板 →「重置 Demo 資料」，或手動清除網站資料 |
